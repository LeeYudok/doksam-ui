# DESIGN.md — 제철과일 판매 모바일앱

## 원형 (archetype)

**주 원형: `split-pane`** (과제 지정 고정값)

- 뼈대: 좌측(모바일에서는 전체 화면) 목록 ↔ 우측(모바일에서는 전체 화면으로 교체) 상세, 페이지 이동이 아니라 "목록 상태 ↔ 상세 상태" 전환.
- 이유: 이 앱의 핵심 행동은 "제철과일 목록을 훑다가 상품 하나를 열어 상세를 보고 다시 목록으로 돌아가기"의 반복이다. 장바구니·주문내역도 형태상 각각 "품목 목록"이라 같은 목록 뼈대를 재사용할 수 있다 — 화면마다 다른 셸을 새로 만들 필요가 없다(사용 빈도가 높고 반복적인 탐색 패턴이라는 사용 맥락 근거).
- 보조 원형: 없음. 4화면 모두 "목록" 또는 "목록에서 전환된 상세" 상태 하나로 설명되므로 두 번째 원형을 섞지 않는다.

## 성격 (personality)

**`elevated`** — scale: regular / surface: shadow / motion: expressive

- 이유: 대외 소비자 대상 구매 화면으로 체류 시간은 짧고(하루 한두 번, 몇 분 내 탐색) 구매 전환이 목적이다. 그림자 기반 표면 위계로 "지금 만질 수 있는 상품 단위"를 배경과 분명히 분리하고, 또렷한 모션으로 담기·수량 변경 같은 조작에 즉각적 피드백을 주는 것이 관리 도구(정보 밀도 우선)보다 이 과제의 사용 맥락에 맞는다.

## 배제 목록 (안 쓸 컴포넌트·패턴)

1. **하단 탭바 안 씀** — split-pane 원형은 상시 탭바 없이 목록↔상세 전환이 내비게이션 역할을 한다. 목적지도 홈/상세/장바구니/주문내역 4개뿐이라 상시 탭바를 깔 만큼 목적지가 많지 않다.
2. **상품 카드 그리드 안 씀 (도메인 기본값 위반 항목)** — 모바일 커머스에서 가장 먼저 손이 가는 기본값이 카드 그리드지만, split-pane의 좌측은 "목록(list)"이지 그리드가 아니다. 390px 폭에서 2열 그리드는 상품명·원산지·중량이 잘려 비교가 어렵다. 세로 리스트 행이 스캔·비교(이번 주 제철 여러 품목을 훑는 행동)에 더 낫다.
3. **sticky 하단 CTA(장바구니 담기 고정 바) 안 씀** — split-pane은 상세를 "모달"이 아니라 "페이지 상태 교체"로 다루는 원형이라, 모달성 고정 UI(sticky bar)를 얹지 않는다. 담기 액션은 상세 본문 흐름의 끝에 두어 사용자가 원산지·중량·상세 설명을 끝까지 읽게 만든다.
4. **Badge + h1 + 설명 문단으로 시작하는 공통 헤더 안 씀** — 홈 화면은 장식적 배지·소개 문단 대신, 사용자가 가장 먼저 봐야 할 값(이번 주 제철 품목 목록)을 상단에 바로 배치한다. 상세/장바구니/주문내역도 각 화면에서 가장 자주 확인하는 값(가격, 합계, 상태)을 헤더 아래 첫 블록에 둔다.

## 화면별 매핑

| 파일 | split-pane 상 위치 | 비고 |
| --- | --- | --- |
| `home.html` | 목록 상태 | 이번 주 제철과일 목록(리스트 행), 상단에 장바구니·주문내역 진입 아이콘 |
| `detail.html` | 상세 상태 (home 목록에서 전환) | 뒤로가기로 목록 상태 복귀, 액션은 본문 흐름 끝 |
| `cart.html` | 목록 상태(장바구니 품목 목록) | 담긴 상품 목록 + 합계 정의 목록 |
| `orders.html` | 목록 상태(주문 목록) | 과거 주문 목록, 상태는 색+텍스트 배지 병기 |

## 색·토큰

시맨틱 CSS 변수만 사용(`--background`, `--foreground`, `--primary`, `--primary-foreground`,
`--secondary`, `--accent`, `--muted`, `--muted-foreground`, `--border`, `--card`,
`--card-foreground`, `--destructive`, `--success`, `--warning`, `--chart-1`~`--chart-3`).
과일 신선함을 연상시키는 그린 계열 `--primary`, 따뜻한 오렌지 계열 `--accent`를 쓰되
색만으로 상태를 구분하지 않고 텍스트를 항상 병기한다(접근성 불변 규칙).
