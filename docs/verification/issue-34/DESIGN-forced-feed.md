# DESIGN.md — 제철과일 판매 모바일앱

## 원형 (archetype): `feed-timeline`

- 뼈대: 상단 얇은 필터 바(제철 카테고리 필터) → 단일 세로 스트림이 화면 전체를 차지(상품/주문 항목은 카드 그리드가 아니라 시간·순서순 한 줄 행). 하단 탭바·사이드바 없음.
- 4개 화면(홈·상세·장바구니·주문내역) 모두 이 뼈대를 그대로 따른다: 상단 얇은 바 하나 + 세로 스트림 한 칼럼. 상세·장바구니도 별도 셸을 만들지 않고 홈과 같은 "상단 바 + 스트림" 구조를 재사용한다.
- 이유: 제철과일은 "이번 주 제철"이라는 시간성이 핵심 데이터다 — 품목이 매주 교체되고, 사용자는 그 주의 순서(신상 → 마감임박)를 훑어보며 담는 저관여·짧은 세션 소비 패턴을 보인다. 항목 간 스펙 비교가 목적인 화면이 아니라 순서대로 흘러가는 큐레이션 스트림이 목적에 맞아 격자 비교형 원형(dashboard-grid 등)보다 feed-timeline 이 낫다. 주문내역 화면은 원형 표의 "감사 로그·이벤트 타임라인" 예시와 정확히 일치한다.

## 성격 (personality): `elevated`

- scale: regular / surface: shadow / motion: expressive
- 이유: 대외 소비자 서비스로 구매 전환이 목적이며, 방문 빈도가 낮고 체류 시간이 짧아(장바구니 담기→결제까지 수 분) 상품 행마다 그림자로 표면 위계를 주고 담기·수량 변경에 또렷한 모션 피드백을 줘야 신뢰감과 조작감을 동시에 준다. crisp(정보 밀도 우선 관리 화면)나 statement(대시보드용 굵은 강조)는 이 소비자 커머스 맥락에 맞지 않는다.

## 배제 목록 (최소 3개)

1. **하단 탭바 안 씀** — feed-timeline 뼈대 자체가 하단 탭바를 두지 않으며, 동시에 모바일 커머스 앱에서 흔히 기본으로 깔리는 요소이기도 하다. 이유: 화면이 홈·상세·장바구니·주문내역 4개뿐이고 각 전환이 스트림 항목 탭 → 상세, 헤더 아이콘 → 장바구니/주문내역으로 충분해 상시 탭 내비를 별도로 둘 만큼 목적지가 많지 않다.
2. **카드 그리드(그리드형 상품 카드) 안 씀** — 모바일 커머스 홈에서 기본으로 채택되는 패턴이지만 feed-timeline 은 항목을 "카드 그리드가 아니라 시간순 한 줄 행"으로 규정한다. 이유: 이번 주 제철 순서(신상 → 곧 마감)를 한눈에 훑는 것이 비교 탐색보다 우선이라, 격자로 흩어놓으면 순서 정보가 사라진다.
3. **화면 하단 고정(sticky) CTA 버튼 안 씀** — 상세 화면에서 "구매하기"를 화면 바닥에 상시 고정하는 것은 커머스 상세의 기본값이지만 쓰지 않는다. 이유: feed-timeline 뼈대의 상시 고정 요소는 상단 필터/뒤로가기 바 하나뿐이다. 여기에 하단 고정 버튼까지 추가하면 원형이 "상단 바 + 스트림" 두 겹이 아니라 "상단 바 + 스트림 + 하단 바" 세 겹이 되어 뼈대가 다른 원형(wizard-flow 등)처럼 보인다. 구매 액션은 상세 스트림의 마지막 행(구매 패널 행)에 자연스럽게 배치한다.

## 톤/색

과일 판매 서비스이므로 원산지 배지·제철 카테고리 구분에 `--chart-1`~`--chart-5`(품목별 계열색)를 쓰고, 강조는 `--primary`(잘 익은 감귤빛 오렌지) 하나로 몰지 않고 `--accent`(잎사귀 그린)를 보조 강조로 나눈다. 재고 임박·품절은 `--destructive`.

## 화면별 스트림 구성

- `home.html` — 상단: 이번 주 제철 카테고리 필터 바(가로 스크롤 pill). 본문: 상품 행 스트림(썸네일 placeholder + 품명 + 산지/중량 + 가격 + 담기 버튼), 마감임박 순으로 정렬된 한 줄씩.
- `detail.html` — 상단: 뒤로가기 + 상품명 얇은 바. 본문: 이미지 placeholder 행 → 가격/중량 선택 행 → 산지·당도 정보 행 → 상세 설명 행 → 리뷰 요약 행 → 구매 패널 행(스트림의 마지막 항목).
- `cart.html` — 상단: 뒤로가기 + "장바구니" 얇은 바. 본문: 담은 순서대로 장바구니 항목 행 스트림(수량 스테퍼 포함) → 마지막 행에 합계·주문하기.
- `orders.html` — 상단: 뒤로가기 + "주문내역" 얇은 바. 본문: 최신순 주문 이벤트 행 스트림(주문일시 + 상태 + 품목 요약) — 원형 표의 "감사 로그·이벤트 타임라인" 그대로.
