# DESIGN.md — 제철과일 판매 모바일앱

## 원형 (archetype)

- **주 원형**: `feed-timeline` — 상단 얇은 필터 바 + 단일 세로 스트림. 홈(이번 주 제철과일 목록), 장바구니(담은 상품 행 목록), 주문내역(주문 이력 행 목록) 3개 화면에 적용.
- **보조 원형**: `wizard-flow` — 상시 내비 없이 본문 한 칼럼 + 하단 고정 액션 버튼. `detail.html`(상품 상세) 1개 화면에 적용. 구매 결정을 내리는 단일 초점 화면이라 목록형 스트림 구조 대신, 하단에 고정된 "담기" 액션 하나로 수렴하는 wizard-flow의 본문 구조를 빌린다.
- **이유**: 제철과일 앱은 목적지가 4개뿐이고 화면당 조작보다 "훑어보고 고른다"가 핵심 행동이다. feed-timeline이 규정하는 얇은 필터 바 + 세로 스트림이 홈/장바구니/주문내역처럼 항목이 위→아래로 쌓이는 화면과 맞아떨어진다. 다만 상세 화면은 목록이 아니라 구매 여부를 결정하는 단일 초점 화면이라 상시 내비 없이 하단 고정 CTA로 끝나는 wizard-flow 본문 구조가 더 맞다.

## 성격 (personality)

- **선택**: `elevated` — scale=regular, surface=shadow, motion=expressive.
- **이유**: 관리 콘솔이 아니라 소비자가 직접 결제까지 하는 대외 서비스 화면이라, crisp(정보 밀도 우선)보다 표면 위계를 그림자로 드러내고 담기/주문 같은 전환 액션에 모션을 또렷이 주는 elevated가 신뢰감·구매 유도에 유리하다. statement의 굵은 스케일은 상품 정보 밀도(산지·중량·가격 병기)를 밀어내므로 제외했다.

## 안 쓸 컴포넌트·패턴 (배제 목록)

1. **하단 탭바 안 씀** *(기본으로 쓰일 법한 것)* — 체류 시간이 짧은 즉흥 장보기 흐름(재고 확인 → 상세 → 담기)에서는 4화면을 상시 오가는 탭바보다, 화면마다 다음 행동 하나(상세의 "담기", 장바구니의 "주문하기")로 시선을 모으는 편이 전환에 유리하다. 화면 간 이동은 헤더의 장바구니/주문내역 아이콘과 상품 탭으로 충분하다.
2. **카드 그리드 안 씀** — 제철과일은 매주 노출되는 품목이 10~20종 내외로 적고, 상품명·산지·중량·가격을 한 줄에서 비교 스캔하는 게 핵심 과업이다. 격자보다 feed-timeline 뼈대의 세로 스트림 행이 더 빠르게 훑힌다.
3. **Table 안 씀** — 장바구니·주문내역은 열 간 정렬·비교가 목적이 아니라 항목별 개별 조작(수량 증감, 재주문)이 목적이라 표보다 설명 행 목록이 맞는다.
4. **Badge + h1 + 설명 문단 통일 헤더 안 씀** — 모바일 세로 스크롤에서 화면마다 똑같은 헤더 블록을 반복하면 스크롤만 늘어난다. 화면마다 가장 먼저 봐야 할 값(홈은 이번 주 산지 태그, 상세는 가격, 장바구니는 합계, 주문내역은 최근 배송 상태)을 맨 위로 올린다.

## 색·토큰

시맨틱 CSS 변수만 사용(하드코딩 색 0건). 신선한 과일 브랜딩에 맞춘 웜톤 그린 + 오렌지 조합:

- `--background`, `--foreground`, `--card`, `--card-foreground`
- `--primary`(과일 그린) / `--primary-foreground`
- `--secondary` / `--secondary-foreground`
- `--muted` / `--muted-foreground`
- `--accent`(제철 강조 오렌지) / `--accent-foreground`
- `--border`, `--ring`
- `--destructive`(품절·삭제) / `--destructive-foreground`
- `--success`(주문 완료·배송중)
- `--chart-1`~`--chart-3`(산지·카테고리 구분용, 색만으로 구분하지 않고 텍스트 라벨 병행)

## 아이콘

이모지 대신 인라인 SVG(단순 stroke 아이콘, Phosphor 스타일의 24px 라인 아이콘을 손으로 벡터화)만 사용.
