# DESIGN.md — 제철과일 판매 모바일앱 (정적 목업)

## 원형 (archetype)

- **주 원형: `dashboard-grid`** — 상단 얇은 카테고리 필터 바 → 본문은 상품/주문 카드를
  2열 격자(또는 세로 목록)로 배열, 카드 클릭이 상세 진입. `home.html`, `cart.html`,
  `orders.html` 3개 화면이 이 뼈대를 쓴다.
- **보조 원형: `doc-reader`** — 좌측 트리·우측 목차는 모바일이라 생략하지만 "중앙
  max-w-prose 본문 한 칼럼" 구조만 가져온다. **`detail.html`** 한 화면에서만 쓴다:
  이미지 → 가격 → 정의 목록(수확시기·원산지·중량·보관법) → 설명 문단 → 리뷰가
  위에서 아래로 한 칼럼으로 흐르는, 조작보다 "읽는" 화면이기 때문이다.
- 이유: 이 앱은 정확히 맞는 원형이 없는 커머스다. 9종 중 구조가 가장 가까운 것은
  "카드 격자 + 클릭 시 상세"인 `dashboard-grid`(지표 카드 대신 상품/주문 카드로
  치환)이고, 상품 상세만은 격자가 아니라 위아래로 읽는 문서형이라 `doc-reader`를
  보조로 썼다. `feed-timeline`은 후보였지만 규정된 회피 조건("항목 수가 20개
  미만으로 고정")에 이번 주 제철과일 목록(6~10종)이 정확히 해당해 제외했다.

## 성격 (personality)

- **`elevated`** (scale=regular, surface=shadow, motion=expressive)
- 이유: 대외 소비자 서비스이고 체류 시간이 짧은 채로 구매 결정을 유도해야 한다.
  카드에 그림자로 표면 위계를 줘서 상품 이미지를 도드라지게 하고, 장바구니 담기·
  결제 같은 전환 동작에 또렷한 모션(살짝의 눌림/트랜지션)을 줘서 피드백을 준다.
  `crisp`(압축 밀도·무모션)는 관리 도구용이라 소비자 쇼핑 경험엔 과하게 사무적이고,
  `statement`(볼드)는 지표 강조용이라 상품 목록엔 과하다.

## 배제 목록 (안 쓸 컴포넌트·패턴, 최소 3)

1. **하단 탭바 안 씀** — 모바일 커머스 앱이면 홈/카테고리/장바구니/마이페이지
   상시 탭바가 기본값이지만, 화면이 4개뿐인 목업에서 상시 탭바를 깔면 콘텐츠
   높이만 줄고 얻는 게 없다. 대신 헤더의 뒤로가기 + 장바구니 아이콘만으로
   4화면을 왕복시킨다. (원형·과제에서 기본으로 쓰일 법한 항목.)
2. **상품 상세 이미지 캐러셀 안 씀** — 카탈로그의 `template-shop`이 상세 화면
   기본값으로 쓰는 패턴이지만, 정적 목업에 다중 이미지 슬라이더를 넣으면 JS 없이는
   상태 전환을 보여줄 수 없고 doc-reader 보조 원형이 요구하는 "위아래로 읽는 단일
   칼럼" 흐름과도 충돌한다. 대표 이미지 1장 placeholder로 대체한다. (원형·과제에서
   기본으로 쓰일 법한 항목.)
3. **Table 컴포넌트 안 씀** — 장바구니 합계(상품금액/배송비/총액)와 주문내역
   모두 열이 3개 이하이고 열 간 정렬·비교가 목적이 아니라 각 행이 읽는 대상이다.
   수렴 안티패턴 절의 지침대로 정의 목록(`<dl>`)과 카드 목록으로 대체한다.

## 색·토큰

시맨틱 CSS 변수만 쓰고 `<style>` 안 `:root`에 선언한다 (`--background`,
`--foreground`, `--card`, `--primary`, `--accent`, `--muted`, `--destructive`,
`--border`, `--chart-1`~`--chart-5`, `--success`, `--warning`, `--radius`).
과일 카테고리 구분은 색만으로 하지 않고 텍스트 라벨(칩)을 항상 함께 쓴다
(접근성 불변 규칙). 폐쇄망 전제상 외부 폰트·이미지·CDN 없이 시스템 폰트 스택과
CSS 배경색 placeholder만 사용한다.
