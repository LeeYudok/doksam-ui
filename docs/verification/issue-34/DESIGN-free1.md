# DESIGN.md — 제철과일 판매 모바일앱

## 원형 (archetype)

- **주 원형: `feed-timeline`** — home / cart / orders 세 화면에 적용.
  - 뼈대: 상단 얇은 필터 바(카테고리 칩 또는 상태 칩) + 단일 세로 스트림(카드 그리드가 아닌 한 줄 행). 하단 탭바·사이드바 없음.
  - home = 제철과일 한 줄 행 스트림, cart = 담긴 상품 한 줄 행 스트림, orders = 주문 한 줄 행 스트림.
- **보조 원형: `split-pane`** — detail 화면에 적용.
  - split-pane 은 "모바일은 목록↔상세 2단 전환"을 뼈대로 명시한다. 이 앱은 화면 폭이 항상 390px(모바일 전용)이라 좌우 분할 자체는 없지만, home 의 한 줄 행을 탭하면 목록이 상세로 완전히 교체되는 전환(뒤로가기로 복귀) 구조를 그대로 쓴다 — 페이지 이동처럼 보여도 "목록 자리 → 상세로 치환"이라는 split-pane 모바일 규칙을 따른 것이다.

## 성격 (personality)

- **`elevated`** — scale=regular, surface=shadow, motion=expressive.

## 배제 목록 (최소 3개, 최소 1개는 원형/과제 기본값)

1. **하단 탭바 안 씀** *(원형·과제 기본값을 깬 항목)* — 모바일 커머스 앱은 보통 홈/검색/장바구니/마이 탭을 하단에 상시 노출하지만, `feed-timeline` 원형 자체가 하단 탭바 없는 스트림+상단 필터 바 구조를 뼈대로 규정한다. 화면 4개가 홈→상세→장바구니→주문 순서로 이어지는 단방향 흐름이라 상시 탭 전환 빈도가 낮고, 장바구니 진입은 헤더의 아이콘+뱃지로 충분하다.
2. **상품 카드 그리드 안 씀** — `feed-timeline` 뼈대가 "카드 그리드가 아니라 시간순/목록순 한 줄 행"을 요구한다. 이 앱은 재구매가 잦은 실사용 목적(장보기)이라 사진보다 산지·중량·가격·당도 텍스트를 빠르게 스캔하는 게 우선이라 그리드보다 행 목록이 사용 맥락에 맞는다.
3. **히어로 배너/캐러셀 안 씀** — `template-shop` 류 커머스 템플릿의 기본 요소이지만, 이 앱은 신규 유입 전환이 목적인 랜딩이 아니라 이미 설치된 앱을 반복 방문하는 유틸리티 화면이다. 체류 시간이 짧고 목적이 명확(오늘 뭐 살지 확인)하므로 스크롤을 잡아먹는 배너 대신 목록을 즉시 보여준다.
4. **Table 컴포넌트 안 씀** — 주문내역은 열 간 비교(정렬·필터링)가 목적이 아니라 "각 주문이 지금 어디까지 왔는지"를 개별적으로 확인하는 목적이라, 표 대신 정의 목록(dl) 형태의 리스트 행으로 각 주문을 보여준다. 모바일 390px 폭에서 표는 가로 스크롤을 유발해 가독성도 떨어진다.

## 색 토큰

시맨틱 CSS 변수로 선언(`--background`, `--foreground`, `--card`, `--border`, `--muted`, `--primary`, `--accent`, `--secondary`, `--destructive`, `--success`, `--warning`, `--chart-1~5`). 과일 판매 앱 맥락에 맞춰 primary 는 잘 익은 과일을 연상시키는 웜톤, accent 는 잎/신선함을 연상시키는 그린으로 정의하고 등락·상태 등은 chart 토큰과 success/warning/destructive 로 구분한다(색만으로 구분하지 않도록 텍스트 라벨 병기).
